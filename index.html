静态出口自检

这一页只干一件事：证明部署管线把文件推到一个静态宿主之后，页面、样式、404、索引策略四样都对。同一个目录可以推到任意一个出口，验完就删。

四段链路

推送整站覆盖，不做增量合并 —— 宿主上不该有本地已经删掉的文件
发布构建/发布状态落到 ready 或 built 才算成功，进程退出码不算
域名默认域名能用，且和清单里登记的地址一致
索引本页标了 index,follow，部署层应换成 noindex —— 页面上看不到，要看源码

为什么这一页是 noindex

它是自检页，不该进搜索。更要紧的是：以后任何一个站从别的宿主搬过来，第一个坑都是「旧地址还在被收录、新地址 canonical 又指回旧地址」。索引策略必须跟着内容走，所以这条链路上 noindex 是硬要求，不是可选项。

各宿主的脾气

  • Cloudflare —— 不解析 _headers（直传通道当普通文件发），改响应头指望不上
  • GitHub Pages —— 完全改不了响应头；必须带 .nojekyll，否则下划线开头的文件被 Jekyll 吃掉；仓库名若等于 <用户名>.github.io 才拿得到根域
  • Netlify —— 认 _headers；团队开了 SSO/密码保护的话，新建站点会默认继承，得单独关掉才是公开的

一个通用坑

仓库/站点名会直接变成域名的一段。名字起错不会报错，只会得到一个又长又难看的地址，而 canonical 一旦跟着写下去，改起来就是一次全站重定向。
